# 04 — The superseded npm scope names the employer

**Blocked by:** None — can start immediately.

**Status:** superseded

## What happens

An earlier, now superseded distribution decision proposed publishing the tool as a scoped npm
package. The scope is the employer's name, and it survives in the superseded record, in the record
that replaced it, and in the design map and grilling notes that fed them.

Nothing about this is confidential on its own. It does link the repository to a named company, and
that link is a choice worth making deliberately rather than inheriting from a proposal that was
declined.

## What I expected

A public repository names the employer where the author wants it named, not in the residue of a
rejected distribution plan.

## Steps to reproduce

1. Search the decision records and the design notes for the scoped package name.
2. Note that every hit belongs to a distribution path that was declined in favour of
   build-from-source.

## Additional context

Two honest options: leave it, on the grounds that a superseded record is history and history should
not be rewritten; or replace the scope with a neutral placeholder and say in the record's comments
that the name was removed before publication. Pick one — do not half-scrub.
